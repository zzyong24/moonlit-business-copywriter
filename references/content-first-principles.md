# 内容首要判断原则

先区分任务：已有观点、口述或稿件的整理与润色，执行当前激活 `moonlit-content-engine/references/editorial-contract.md` 的“作者表达优先：信达雅”；不把下文七问、证据或论证检查套成改稿门槛。下文用于用户请求的从零策划、选题和研究。

先回答：这条内容为什么值得处于某个情景中的人看，我们能凭什么兑现这份价值。此原则先于象限、脚本类型、对标结构、钩子和商业承接；不是传播效果保证，也不是必须照念的七段模板。

## 起稿前七问

1. **人和处境**：主要讲给谁，他现在处在哪个阶段与情景？身份标签不能替代处境；允许其他人受益，不必虚构一个精确画像。
2. **关切及依据**：围绕哪个问题、经历或现象，回应他的困惑、困难、愿望或好奇？来自评论、沟通、观察、同类经历还是待验证假设？假设可用于出题，不能冒充普遍需求。
3. **观看后的变化**：希望他多明白、分清、判断、尝试或感受到什么？选一个主要方向，允许相关的辅助收获；不强制操作、清单或转化。
4. **材料与支持关系**：事实、经历、案例、观察分别能支持什么？列出来源与限制；材料不足时可设计研究，不提前写成已有结果。
5. **未知与分歧**：哪些未明之处会改变答案？怎样核验，什么结果会让我们改变判断？没有实质分歧时不制造争论，也不先定结论再找证据。
6. **帮助范围**：本条能帮到哪一步，哪些还不能推出？影响理解、决策或可迁移性的重要限制要自然写入正文；审稿状态标签留内部。
7. **表达选择**：在以上基础上选择解释、演示、探索、叙事或纠错，再归类象限、选结构和包装。CTA可无；商业任务不得替代观众收益。

选题阶段可标暂定受众、需求假设和planned证据，并说明下一步验证。成稿可以保留未知，清楚交代观察和不足就是有效结果；不得把未完成实测写成已经发生。

## 按任务组织

|表达任务|可用推进|不必具备|
|解释|相关现象/问题 → 关键区分或机制 → 例子与条件 → 理解收获|旧观点、反转|
|演示|想完成的事 → 操作与观察 → 检查结果 → 适用条件|失败剧情、强结论|
|探索|真实疑问 → 已知材料 → 不同解释/未知 → 目前可判断部分 → 下一步|确定答案、赢家|
|叙事/复盘|处境 → 当时选择 → 发生的事 → 认识如何变化 → 现在的取舍|普遍规律、成功结局|
|纠错|有依据的原观点 → 具体问题 → 解释与证据 → 修正范围|对立人群、攻击语气|

只在确有需要修正的观点时，说明原观点来源、解释了什么、在哪些条件下依据不足，以及哪些证据支持修正。不得把观众描写成愚昧的假想对手。

## 写作检查

- 标题、开头、主体和结尾是否兑现同一种主要价值？开头可用问题、结果、细节或好奇，不强制痛点/矛盾。
- 策划中的范围讨论只服务该策划任务；作者已有表述的写作保留原有条件，不自动增写限定或规避性话术。
- 区分写稿返工与真实经历：无关的编辑过程不进入正文，真实失败、改主意、纠正认识可构成重要证据，不塑造成从一开始就正确。
- 复盘看观众是否更能区分/判断/实践或是否产生相应感受；评论与反馈只是信号，点赞不自动证明理解或商业效果。

## 共同交接字段

content_brief：audience_situation、concern、concern_basis（证据/假设）、intended_change、materials_support、open_questions、revision_evidence、help_scope、limitations、expression_mode。无分歧/无需纠错可以明确not_applicable；不要为填表制造未知。

先完成此简报，再填quadrant、structure_reference、CTA（null允许）、commercial_hypothesis。历史记录未包含这些字段时补查或标unknown，不能假设早期选题已过本原则检查。
