# 事实核查与故事机制设计

用于把产品体验、商业判断和零散口述变成可讲、可信、可迁移的内容。先分清证据，再寻找故事；不为完整流程而制造不需要的研究。

## 何时使用

- 口播包含产品功能、定价、用户规模、营收、成本、发布时间、政策、市场表现等外部事实。
- 用户提出了“因为 A 所以 B”的解释，尤其涉及产品更新带来的留存、营收、传播或社区变化。
- 用户要求核查观点、展开故事、找历史/跨行业类比，或材料明显需要这两步。
- 个人经历可作为经历本身的证据，但不能自动证明行业规律、产品整体表现或因果关系。

纯体验分享若只陈述“我在某日做了某事、遇到某问题、因此作出某个个人选择”，不必强行扩展成外部研究。若它进一步推导产品功能、商业效果或普遍建议，再核查对应主张。

## 第一步：拆开主张

把输入拆为四类，逐条记录，不将它们写成一个混合结论：

1. **亲历 / 一手材料**：作者亲自做过、看过或收到的内容。标明时间、版本、设备、任务与观察范围；个人回忆仍应标成作者口述，不能冒充公开核验。
2. **外部事实**：能由公开来源核实的时间、功能、价格、政策、数据、产品边界或第三方案例。
3. **推论**：从事实导出的判断，写出中间机制和需要成立的假设。
4. **价值判断**：好坏、值得、适合、应该等带偏好的判断；说明面向谁、按什么目标判断。

建立一个精简主张表：`主张 | 类别 | 证据/来源 | 时间和适用范围 | 状态 | 对正文的处理`。只研究会改变观众判断的关键主张；不必把每句个人感受都做成查证项目。

## 第二步：核查外部事实

联网检查来源、原始上下文、发布日期/生效日期、样本或口径、地区/版本限制，以及来源是否有利益关系。优先顺序：官方产品/政策/财报/原始数据；可追溯的一手记录；高质量独立报道或研究；其余来源只作线索。厂商营销页能证明厂商当前如何描述产品，不能独立证明性能、市场成功或用户效果。

为每个事实标注以下之一：

- **已证实**：找到直接、足够可靠且上下文匹配的证据。
- **基本成立，但需要收窄**：方向可支持，但时间、版本、地区、样本或适用范围比原说法窄。
- **存在争议**：可靠来源互相冲突，或定义/测量口径不同。
- **证据不足**：没找到足够证据；不能写成事实，也不能用“没有找到”证明其反面。
- **明显错误**：直接证据与主张相反。

标状态时同时记证据日期。产品当前文档不能反向证明旧版本当时的行为；动态价格和规则需在发布前复核。第三方营收估算、估值或员工数若无透明方法和一手佐证，不称为“公司数据”。没有可靠披露时直说“未找到可核实的公开营收数据”，并将论证转向可观察的定价机制，不能用模糊估值补空。

## 第三步：审推理链

对重要结论逐项检查：

1. 事实是否足以推出结论？把缺失的中间机制写出来。
2. 有没有把同时发生当成因果？需要什么对照、数据或机制证据？
3. 有没有隐含前提，如用户会迁移、愿意付费、使用频次增长、成本真由本地承担？
4. 有没有反向解释或遗漏变量，例如新增功能、渠道投放、价格变化、季节性、样本偏差？
5. 在什么用户、工作负载、成本结构和经营阶段下成立？何时失效？

给推论分层：**可直接说**、**加条件后可说**、**只能作为待验证假设**。若没有营收、留存或转化数据，不得判断某次产品形态变化“提升了营收/社区”；可解释商业机制的可能性，并明确这是推论。

## 第四步：把专业问题翻译成故事问题

先暂时拿掉产品名与行业词，用一两句写出普通人也能理解的处境：谁想得到什么、被什么成本或摩擦拦住、现有做法为什么不够。再提炼：

- **底层结构**：参与者、资源、约束、交换与反馈分别是什么？
- **核心矛盾**：两种都重要、但互相牵制的目标是什么？
- **普通解法为什么失效**：它把成本转嫁给谁、把哪一环留在原地、或为何没有持续反馈？

只在类比能让结构更清楚时做跨领域研究。通常选一个历史案例和至少三个距离较远的领域；主题简单时可以少做，并说明原因。跨域距离看机制是否不同，不靠罗列行业名凑数。

**案例地域默认配比**：当作者没有另行指定时，故事案例尽量做到约 60% 中国/本土案例、约 40% 海外案例；案例数较少时取最接近的整数（如 5 个选 3 个国内、2 个海外）。国内案例优先找原始中文材料、公司年报/官方产品规则、政府和行业机构来源；海外案例也按同样标准找原始来源。地域配比是选材偏好，不是牺牲相关性或证据质量的硬指标：找不到可靠来源或机制不匹配时，少用一个并说明，不为了凑比例造例子。交付案例卡时标注国家/地区、领域和来源类型，方便检查比例是否真实。

每个候选案例用五句卡片整理：

1. 那个领域当时遇到什么具体问题？
2. 它采用了什么机制？
3. 与本题共享的结构是什么？
4. 哪一部分能迁移为产品/经营动作？
5. 类比在哪些条件下失效？

用可信的一手或权威来源确认案例。历史先例不是普遍因果定律；行业机制相似也不表示规模、监管、用户行为或经济性相同。若可靠来源不足，就标为待核验或不用。

## 第五步：选机制，落成实验

从案例里选最值得借用的三个机制，不照搬故事外壳。将每个机制翻译为：`要降低的摩擦 / 要重新分配的成本 / 要建立的反馈 → 当前能做的具体动作 → 观测指标 → 失效条件`。至少推荐一个低成本、可逆实验，明确人群、时间/样本、比较方式、停损条件和能回答的问题。没有足够样本时称为探索，不称为验证结论。

## 交付模板

按用户实际请求选择深度，不固定输出大报告：

```text
主张拆解：亲历 / 外部事实 / 推论 / 价值判断
事实核查：状态、证据、日期/范围、建议说法
推理检查：关键假设、其他解释、成立/失效条件
底层故事：处境、结构、核心矛盾、普通解法的局限
案例卡：问题、机制、相似点、可迁移点、失效边界
三个可借机制：分别转成当前处境的动作
建议先试：低成本、可逆实验与观测指标
内容处理：可说 / 需收窄 / 标为个人体验或假设 / 删除
```

用户给出两段提示词时，按上述阶段执行其意图，不机械复述提示词，不用格式替代判断。研究结果回到观众问题与口播表达：正文只保留支撑核心判断所需的事实、边界和故事机制；完整来源、争议及未用案例放在脚本外的研究记录中。
