# 写作加法工具箱

`negative-prompts-100.md` 和状语补语硬门负责“删”；本文件负责“加”：让句子有画面、口播有节奏、开头有理由。删和加都不改作者的观点、事实和数字（见 `moonlit-content-engine/references/editorial-contract.md`）。用法：成稿前先删一遍，再用本文件的招数加一遍，每篇挑 2–3 招，不要全用。

下面的“原句”取自月明已发布口播《没辞职，AI副业半年变现约5万》（2026-10）。“改后”只演示手法，用时以作者本期原意为准。

## 一、六招

### 1. 具体化：把概括换成一个看得见的东西

抽象词出现时，问“具体是哪一个/哪一次/多少”。能给一个具体对象，就不用概括词。

- 原句：我做了十来个产品，最后推出去的只有两三个。
- 加法：保留原句，后面补作者真实的一个例子：“比如 AI 童伴，＿＿＿。”（横线处只填作者讲过的事，没有就不补）
- 检查：观众能不能在脑子里“看见”一个具体的东西？

### 2. 数字锚点：让数字可感

大数字配一个日常参照，小数字配一个对比。数字只用作者给的，参照物要真实可算。

- 原句：累计用了 65,434,822,287 个 token。
- 加法：“654 亿 token。”后接一个算准的参照，例如换算成多少本书或多少天的连续对话（参照数先算准再说，算不准就不加）
- 检查：去掉参照后，观众是否只记得“很多”？

### 3. 动作化：把判断换成一个动作

“解决了 X 问题”“提升了效率”这种结果句，换成谁在什么时候做了什么。

- 原句：它想解决的问题其实很简单。
- 加法：“它只做一件事：你把孩子和 AI 的聊天记录贴进来，它告诉你哪几句有问题。”
- 检查：这句话能不能直接拍成一个镜头？（能拍 → 也就有了 B-roll 触发词）

### 4. 比喻：用一个日常东西讲清一个关系

只在关系难懂时用，一期内最好与本期母意象（`creative-concept.md`）同源。比喻要说清“像在哪里”，不要只给形容词。

- 原句：在公司里，我只负责后端这一环。
- 加法：“公司像一条流水线，需求有人提，设计有人做，我只拧中间那一颗螺丝。”
- 检查：比喻对象观众是否都见过？比喻是否对应原关系的结构，而不只是气氛？

### 5. 问句的正确用法：替观众问出他心里那句

问句只在观众真的会这么想时用，问完马上答。禁止连环空问、反问凑气势。

- 原句：最后为什么推出去的只有两三个？
- 这是好问句：它是观众听完“十来个产品”后自然冒出的疑问，而且下一段就回答。
- 检查：问完 3 秒内有没有开始回答？

### 6. 口播节奏：写给耳朵，不是写给眼睛

- **一句一个信息**：一口气说不完的句子拆开。中文口播单句建议 ≤ 20 字，最长不超过 30 字（1.13 倍速后仍要听得清）。
- **长短交替**：两三句展开后，用一句 4–8 字的短句收住（“就这么简单。”“三个。”）。
- **重音落句尾**：把要强调的词放在句尾。字幕跳色、动效触发都落在这个词上。
  - 原句：我累计变现了大概五万块钱 → 重音“五万块钱”在句尾，好。
  - 反例：五万块钱是我过去半年大概累计变现的 → 重音被埋在句首。
- **给画面留气口**：要出图解、数字、演示的地方，前一句结束后留 0.3–0.5 秒，或用“你看——”这类短引导。
- **朗读检查**：逐句读出声，卡口的地方改成日常说法；读不出重音的句子重写。

## 二、钩子选型（替代“必须有冲击力/反常识”）

开头的任务是让目标观众在 3 秒内认出“这和我有关，继续看有收获”。按本期材料**选一种**，不要叠加：

| 类型 | 什么时候用 | 例（据作者原意改写） |
| --- | --- | --- |
| 结果型 | 有真实结果 | “过去半年，我没辞职，靠 AI 副业变现了大概五万。” |
| 数字型 | 有一个能单独成立的数字 | “十来个产品，活下来的只有两三个。” |
| 场景型 | 有一个具体时刻 | “过年那几天，我发现小外甥一直抱着手机和 AI 聊天。” |
| 问题型 | 观众本来就在问 | “Hermes 是什么？Skill 又是什么？” |
| 反常识型 | **仅在有证据**推翻一个常见做法时 | “做了十个产品之后，我发现先写代码是最慢的那条路。”（需作者确有此判断） |

规则：

- 钩子必须在正文兑现；开头承诺的东西，正文里要能指出在哪一段给。
- 作者原稿已有钩子时保留原钩子，只做节奏和重音调整。
- 不用：“很多人以为……”“你一定不知道……”“99% 的人……”“家人们”“谁懂啊”。

### 各平台用哪种

| 平台 | 优先 | 说明 |
| --- | --- | --- |
| 短视频口播 | 结果型、场景型、数字型 | 前 3 秒配画面：说到数字时数字弹出 |
| 小红书标题/首句 | 结果型、数字型、问题型 | 可用 1 个与内容相关的 emoji，不堆砌 |
| X 短帖/线程首帖 | 结果型、反常识型（有证据时） | 前 10 字给出结果或对象，不卖关子 |
| 朋友圈 | 场景型、结果型 | 像跟熟人讲一件刚发生的事 |
| 公众号导语 | 场景型、问题型 | 可以慢一点，第一段交代“这篇帮你解决什么” |

## 三、钉子句（可截图的一句话）

钉子句是把整篇的判断压成一句能被转述的话。它不是装饰，也不是必须。

- **可以写**：作者已有明确判断，且正文给了支持它的经历或证据。
- **怎么写**：主语具体、一个判断、≤ 20 字、能脱离上下文成立。例：“AI 的问题不是不会写，是写完就忘了为什么这样写。”
- **不写**：探索题、证据不足、作者本人态度未定时；不用空泛哲理（“慢就是快”）。
- 朋友圈、X 短帖可以以钉子句收尾；没有合格的钉子句就自然结束，不硬凑。
